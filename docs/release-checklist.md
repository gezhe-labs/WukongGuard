# 后悔药发布检查

## 已可自动检查

- `WukongGuard.Tests` 规则与触发边界检查。
- Mod、覆盖层、启动器分别编译；构建玩家单文件 EXE。
- 对发布包运行 `--verify`；在模拟游戏目录运行 `--install`、`--disable`，核对配置备份、版本标记、文件完整性和退出清理。
- 首次准备只在需要写入游戏目录时请求管理员权限，并仅给当前用户在后悔药 Mod 子目录的修改权限；日常启动以普通用户运行。Steam 更新若重置该目录权限，会再次请求授权修复。

## 仍需真实游戏验收

- 首次打开 EXE → 待命 → Steam 启动游戏 → 运行时状态正常 → 游戏退出后停用。
- 与常用修改器同时运行，确认 `Console=0` 和 `EnableJit=0` 仍兼容。
- 游戏内普通提醒、10 秒自动关闭、键盘进入详情、手柄 Menu/A/B 与焦点返回。
- 逐条核对 7 条不可补救提醒及 6 条隐藏地区提示的距离、时机和完成后抑制；目前只有第一章幽魂风险点做过一次正向验收。
- 在新周目及多周目分别验证规则，不把地点命中误称为任务状态验证。

## 发布前人工检查

- 在新 Windows 用户配置下检验 Steam 检测、首次联网准备、更新、退出以及错误恢复。
- 检查 Loader 许可证和再分发要求；确认 GitHub Release 附件的 SHA256 与 `--verify` 结果。
- 确定代码签名或明确展示未签名 EXE 的 Windows 安全提示；商标与产品名称做正式核查。
- 以上真实游戏验收完成前保持候选版标识，不宣称六章已经完整验证。
